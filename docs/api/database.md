# Schema, queries, and database

[Usage reference](../../usage.md) · [Application API](application.md) · [Storage API](storage.md)

## Example model

Save this shared module as `model.ts` when using the examples in this reference.
It is safe to share between client and server builds.

```ts
import { boolean, hydb, id, index, text, timestamp } from "@hyos/hydb";

export const projects = hydb.table("projects", {
  id: id().primaryKey(),
  ownerId: id().notNull(),
  name: text().notNull(),
});

export const tasks = hydb.table("tasks", {
  id: id().primaryKey(),
  projectId: id().notNull().references(() => projects.id),
  title: text().notNull(),
  done: boolean().notNull().default(false),
  createdAt: timestamp().notNull(),
}, (columns) => [index("tasks_by_project").on(columns.projectId)]);

export const schema = hydb.schema({ projects, tasks });
export const taskList = hydb.query(tasks)
  .orderBy((task) => [task.createdAt.desc(), task.id.asc()])
  .many();
```

## Schema builders

| API | Contract |
| --- | --- |
| `hydb.table(name, columns, defineIndexes?)` | Binds column definitions to a named table. The optional callback returns index definitions using those bound columns. |
| `hydb.schema({ tables... })` | Builds the schema; validates table identity/names, primary keys, and that referenced columns belong to the schema. Reuse the actual table objects throughout queries, policies, and storage. |
| `hydb.enum(name, values)` | Returns a callable column builder for a string union; use `const status = hydb.enum("status", ["open", "closed"]); status().notNull()`. |
| `id()`, `text()` | String columns. IDs are supplied by the application, not generated by the builder. |
| `integer()`, `number()` | Numeric columns. Validate external numeric values with command input schemas. |
| `boolean()` | Boolean column. |
| `timestamp()` | `Date` column, not an ISO string. |
| `json<T>()` | A typed structured value; this generic is not a runtime Zod validator. Keep persistent values within the [row codec's limits](storage.md#stored-values). |
| `index(name).on(first, ...rest)` | Non-unique index, including compound indexes in declared column order. |
| `uniqueIndex(name).on(first, ...rest)` | Enforces uniqueness for the indexed tuple at storage commit. |

Every column builder supports `.notNull()`, `.default(value)`, `.primaryKey()`,
and `.references(() => anotherTable.column)`. Columns are nullable by default;
`.primaryKey()` also makes them non-null. Marking multiple columns as primary
keys creates a composite key in column declaration order. Supply those keys as
arrays, for example `[organizationId, taskId]`, to transaction/storage methods.

Defaults are values, not callbacks. Transaction insertion clones supplied/default
values and fills omitted nullable fields with `null`. Required fields without a
default must be supplied. Update patches exclude primary-key columns. Use Zod
contracts to validate incoming values; schema typing does not replace boundary
validation. References describe relationships, not automatic foreign-key checks
or cascades.

`InferRow<typeof tasks>` is the materialized row, `InferInsert<typeof tasks>` makes
nullable/defaulted insert fields optional, and `InferUpdate<typeof tasks>` is a
partial patch excluding primary keys.

Source: [schema.ts](../../packages/hydb/src/schema.ts).

## Query builder

Start with `hydb.query(table)`. Builder calls return new descriptions; finish with
a cardinality method to obtain a `Query<Result>` that can be fetched/subscribed to.

| Method | Behavior |
| --- | --- |
| `.where(row => expression)` | Adds a filter. Repeated calls combine filters with AND. |
| `field.eq(valueOrField)`, `field.ne(valueOrField)` | Equality and inequality; compare with a literal of the field type or another field expression. |
| `expression.and(other)`, `.or(other)`, `.not()` | Compose boolean expressions. |
| `.orderBy(row => field.asc())` | Ordering; return an array for multiple keys. A later `orderBy` replaces the previous ordering. |
| `.limit(count)` | Caps matching rows before final cardinality/projection. Supply a non-negative integer. |
| `.select(row => ({ ... }))` | Select fields or nested terminal queries. Without it, return full table rows. |
| `.many()` | `Query<Row[]>`; empty results are `[]`. |
| `.one()` | `Query<Row \| null>`; throws if more than one row matches. |
| `.require()` | `Query<Row>`; throws unless exactly one row matches. |
| `.exists()` | `Query<boolean>`. |
| `.count()` | `Query<number>`; counts matching rows after any limit. |

Use `.orderBy(...).limit(1).one()` for a first-or-null result. `.one()` by itself
is a cardinality assertion, not a first-row shortcut. High-level predicates do
not currently expose `gt`, `gte`, `lt`, `lte`, `in`, or arbitrary JavaScript
predicates; range scans exist at the storage layer.

Nested queries provide correlated relationships and counts:

```ts
import { hydb, type InferQueryResult } from "@hyos/hydb";
import { projects, tasks } from "./model.js";

export const board = hydb.query(projects).select((project) => ({
  id: project.id,
  name: project.name,
  openTasks: hydb.query(tasks)
    .where((task) => task.projectId.eq(project.id).and(task.done.eq(false)))
    .select((task) => ({ id: task.id, title: task.title }))
    .many(),
  taskCount: hydb.query(tasks)
    .where((task) => task.projectId.eq(project.id))
    .count(),
})).many();

export type Board = InferQueryResult<typeof board>;
```

A query object is a description, not a callable function or network payload.
Register reusable objects for HTTP reads; the browser transport maps objects to
names by identity. Result values are materialized/cloned, and subscribers receive
complete query results rather than storage change batches.

Sources: [query.ts](../../packages/hydb/src/query.ts),
[executor.ts](../../packages/hydb/src/executor.ts).

## Database lifecycle and operations

```ts
import { hydb, memoryStorage } from "@hyos/hydb";
import { schema } from "./model.js";

export async function openTestDatabase() {
  const storage = await memoryStorage({ schema });
  return hydb.database({ schema, storage });
}
```

`hydb.database({ schema, storage, memory?, spill? })` returns `Promise<Database>`.
It owns the supplied storage. `memory` is a `MemoryManager` or `{ maxBytes }`
(default 128 MiB); `spill` is a `SpillOptions` object. Share a manager with a
persistent engine if you want its page cache in the same accounting budget.
See [runtime resources](runtime.md) for spill ownership and limits.

| Database API | Result and lifecycle |
| --- | --- |
| `fetch(query)` | `Promise<InferQueryResult<Q>>`; opens/closes one consistent snapshot. Raw reads have no principal/read-policy filtering. |
| `subscribe(query, listener)` | Returns a synchronous unsubscribe function. Initial data arrives asynchronously, then updates. Raw database subscriptions have no `onError` argument. |
| `transact({ principalSchema, principal, defaultPolicy }, callback)` | Policy-aware transaction. Awaits the callback; commits its buffered mutations or aborts them on failure. Returns the callback result. |
| `execute(legacyCommand, input)` | Runs a legacy HyDB command; distinct from HyApp gateway `dispatch`. |
| `memoryStats()` | Current managed-memory counters and ownership totals. |
| `close()` | Aborts change consumption, disposes subscriptions, drains their cleanup, and closes storage. Always await it. |
| `getDatabaseSchema(database)` | Returns the schema associated with a database created by this package. |

The runtime operates on `main`, serializes its command queue, and commits against
an expected snapshot head. Successful writes wait for local subscriptions to
process the published commit sequence, not for remote browser rendering. An
input/policy/output validation failure before commit publishes no changes. If a
change-stream failure or response loss happens after publication, an observed
error is not proof that the write rolled back.

Prefer gateway reads for application users. Use direct database reads only in
trusted backend logic/tests. Call unsubscribe when consumers are disposed;
`close()` is the final owner's responsibility. For HTTP/Solid subscription errors,
use the [application adapters](application.md).

## Transactions

HyApp server handlers receive the same `Transaction` as `database.transact`.
Its methods are asynchronous; await every write. Reads see the transaction's own
staged changes. The transaction becomes inactive when its callback finishes.

| Method | Contract |
| --- | --- |
| `get(table, key)` | Row or `undefined`; this is a trusted transaction read, not a gateway-filtered query. |
| `insert(table, values)` | Applies defaults, authorizes, stages insertion, and returns the resulting row. Duplicate primary keys reject. |
| `update(table, key, patch)` | Authorizes before/after state, stages a patch, and returns the resulting row. Missing rows and primary-key changes reject. |
| `delete(table, key)` | Authorizes and stages deletion; missing rows reject. |
| `withAdminPolicy(callback)` | Scoped write-policy override requiring explicit authorization assertions; see [authorization](application.md#authorization). |

There is no transaction `fetch`, arbitrary query, or nested transaction method.
Use `get` for authorization reads, and keep external side effects outside the
transaction's rollback assumptions. Transaction rollback does not undo a sent
email or other external service operation.

## Inspecting plans

`planQuery(schema, query)` returns a `PhysicalQueryPlan` for diagnostics; it does
not execute the query or add gateway authorization by itself. Its fields are
`source`, `access`, `filters`, `order`, `limit?`, `cardinality`, `join?`,
`authorization?`, and `selection?`.

`PhysicalAccess` selects `primary-key`, `table-scan`, or `index-scan`.
`PhysicalJoin` selects `indexed-loop` or `hash`. `PhysicalAuthorization` describes
a parent-through filter. `PlannedValue` is a literal or outer-field reference;
`PlannedSelection` maps fields to expression or nested-query entries described by
`PlannedSelectionValue`. Prefer indexes for correlated lookups; the planner may
otherwise choose broad scans/hash work.

Source: [planner.ts](../../packages/hydb/src/planner.ts).

## Legacy HyDB command and gateway APIs

Keep existing callers working, but use HyApp for new application composition.

- `hydb.command({ input, handler(transaction, parsedInput) })` returns a legacy
  `Command<Input, Result>`. There is no HyApp-style `server`, `optimistic`, or
  output-schema option. Run it with `database.execute(command, input)`.
- `hydb.gateway({ database, principal, commands, readPolicies })` returns a
  legacy `Gateway` with `.commands` and `.forPrincipal(principal)`.
- Its session exposes `fetch`, `subscribe`, and **`execute(name, input)`**.
  HyApp instead takes a `registry`, exposes `.registry`, and uses **`dispatch`**.
- Legacy commands do not use HyApp's default write-policy enforcement; the
  legacy gateway filters reads but does not make legacy writes principal-aware.
- Legacy type exports are `Command`, `InferCommandInput`, `InferCommandResult`,
  `Gateway`, `GatewayCommands`, `GatewaySession`, and `InferGatewayCommands`
  from `@hyos/hydb`. Import HyApp's versions for HyApp objects.

Sources: [legacy command](../../packages/hydb/src/command.ts),
[legacy gateway](../../packages/hydb/src/gateway.ts).
